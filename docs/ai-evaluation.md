# Retrieval and grounding evaluation

These numbers come from small, self-authored Arabic test sets. They show whether a change helped on those sets. They are not an accuracy estimate for real use, and they say nothing about the external model. `validated_for_release` stays `false`.

Reproduce: `npm run build`, then `node tests/tool-search.eval.mjs _site/search-tools.json` and `node tests/grounding.eval.mjs`.

## 1. Smart search: candidate retrieval (`site/tool-search.js`)

Change: light Arabic stemming, a small Arabic-to-name vocabulary table, BM25-style scoring over the full description and the tool name, and abstention when the query has no known task vocabulary or the best score is weak. The previous method matched only the name and first sentence of the description by substring.

Data: 1,128 tools. Query sets are in `tests/data/tool-queries.json`: 20 dev queries (used while tuning the vocabulary table and threshold), 20 held-out queries written before tuning, 8 out-of-scope queries (also used to set the abstention threshold).

| Set | Method | recall@5 | recall@15 | hit@5 | MRR |
|---|---|---|---|---|---|
| dev (20) | previous | 0.208 | 0.431 | 0.35 | 0.252 |
| dev (20) | current | 0.616 | 0.857 | 0.90 | 0.721 |
| held-out (20) | previous | 0.285 | 0.511 | 0.50 | 0.327 |
| held-out (20) | current | 0.517 | 0.824 | 0.80 | 0.617 |

Abstention: on 8 out-of-scope queries the previous method returned results for 7; the current one returns none. Cost: 3 of 40 in-scope queries are wrongly refused (7.5%).

Limits: relevance labels were judged by the author; the vocabulary table is hand-made and covers common investigation tasks only; the held-out set is small, so the held-out gain is the figure to trust more.

## 2. Page support check in the Worker (`supportOf` in `worker/rag-worker.js`)

Change: stemmed term overlap; numbers must appear in the best sentence or its neighbours (not anywhere on the page); a best sentence whose negation parity differs from the claim is not treated as support. The negation rule is a weak heuristic (a plain "لا" in an unrelated clause can trigger it).

Data: 25 claim/page pairs in `tests/data/grounding-cases.json`. The negation and distant-number cases were written to exercise the new rules, so the gain on them is by design.

| Rule | Correct decisions |
|---|---|
| previous | 12 / 25 |
| current | 24 / 25 |

The remaining miss is a broken-plural case (الوزراء / الوزير) that a light stemmer cannot join. The change does not alter model prompts, and it needs a Worker deployment to take effect on the live site.

## 3. Smart search: full-catalogue semantic ranking (worker mode `semantic_catalog`)

Change: the experimental semantic re-rank previously scored only the top-12 keyword candidates (the worker's `semantic` mode). A new worker mode ranks the WHOLE catalogue server-side: every tool's bge-m3 embedding is precomputed once locally (`scripts/build_embeddings.py`, int8-quantized, `site/tool-embeddings.{json,bin}`), the worker embeds only the question and returns the top-60 indices; the client RRF-fuses that ranking with the keyword candidates (`fuseSemanticCatalog`, k=60) and applies the same scope-gating. When keyword search abstains entirely, floor-gated (cosine >= 0.5) semantic-only suggestions are shown ONLY when the existing abstention gates do not apply: transactional intent, capability gaps (anchor miss) and uncovered jurisdictions stay abstained exactly as before - semantic similarity never overrides them. If the worker's asset fingerprint does not match the deployed catalogue, or the fetched bin fails the manifest's sha256, the client falls back to the previous 12-candidate path.

Data: the same 20 dev / 20 held-out / 8 out-of-scope self-authored sets, with query embeddings generated by the same model and quantization as the catalogue asset (`tests/data/semantic-fixture.json`); the eval runs offline (`tests/semantic-catalog.eval.mjs`). Provenance: the 20 dev queries AND the 8 out-of-scope queries are DEV data here - the 0.5 floor was chosen from them (non-adjacent out-of-scope tops max 0.457; in-scope tops min 0.553 in the dev sample), so the out-of-scope row below is a dev result, not an untouched test. The 20 held-out queries remain untouched by any tuning. Relevance labels are author-judged against the catalogue's own capability descriptions, as in section 1. Measured 2026-10-30 on the committed assets:

| Set | Method | recall@5 | recall@15 | hit@5 | MRR |
|---|---|---|---|---|---|
| dev (20) | 12-candidate rerank | 0.628 | 0.762 | 0.95 | 0.774 |
| dev (20) | full-catalogue | 0.633 | 0.901 | 0.95 | 0.749 |
| held-out (20) | 12-candidate rerank | 0.498 | 0.678 | 0.75 | 0.601 |
| held-out (20) | full-catalogue | 0.537 | 0.958 | 0.85 | 0.620 |

Out-of-scope (dev-labeled): the 12-candidate path shows nothing for all 8 queries (keyword abstains, nothing to rerank); the full-catalogue path also shows nothing for all 8 - the transactional-intent gate blocks the used-car query that would otherwise surface a car-identification tool, and the rest fall below the floor. The candidate populations differ by design (12 keyword candidates vs the whole catalogue); both ranked lists are URL-deduplicated exactly as the UI displays them.

Quantization loss (int8-per-vector vs local fp32 round-trip, NOT Cloudflare parity): mean |cos - 1| = 0.000149, max 0.000400, measured on all 1,156 tools.

Parity (PASSED 2026-10-30, before merge): live Workers AI `@cf/baai/bge-m3` query vectors vs the local ONNX int8 asset - encoder cosine mean 0.9816 (min 0.9694), production-configuration top-10 ranking overlap mean 8.8/10, and the full fused path with live CF vectors keeps the held-out gain (recall@15 0.929 vs the 0.678 baseline; out-of-scope 0/8). Full record in `docs/deployment.md`. Author-labeled relevance and small sets remain the main caveat, as in section 1.
